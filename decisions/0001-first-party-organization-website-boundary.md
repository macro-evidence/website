# 0001. First-party organization website boundary

**Status:** Accepted
**Date:** 2026-09-11

## Context

Macro Evidence needs a first-party institutional website that creates value beyond a repository index while keeping Macro Data Observatory's technical and product depth with the platform that owns it.

## Decision

`macro-evidence.com` is the Macro Evidence organization website. It presents the organization's mission, work, operating principles, public governance, participation routes, trust boundaries, and official identity resources.

Macro Data Observatory remains the flagship and foundational platform. The organization website may explain that relationship and route visitors to MDO, but it does not duplicate volatile product documentation, provider inventories, APIs, catalogue behavior, or future MDO product surfaces.

Canonical governance, policy, contribution, and security records remain authoritative in the repositories that own them. The website provides concise first-party orientation and explicit links to those canonical sources when deeper material is needed; it does not maintain a second publication copy of the record corpus.

## Consequences

- The website must stand on its own rather than function as a GitHub redirect.
- Organization and platform identity remain distinct.
- Current product capability claims must be derived from current MDO evidence rather than organization positioning.
- Website copy can evolve without turning every editorial revision into a governance-document rewrite.
- Deep institutional records may require an explicit transition to their canonical GitHub source, and that destination must be clear before activation.
